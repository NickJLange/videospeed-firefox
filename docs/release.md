# Release runbook

## Validate and build

Use Node.js 22.13+ and npm. `package.json` is the version source of truth; keep the root
`manifest.json` version in sync. The build copies that version into `dist/manifest.json`.

```sh
npm ci
make test
make clean && make build
node tests/e2e/validate-extension.ts
nix develop --command web-ext lint --source-dir=dist
npx puppeteer browsers install firefox
npm run test:firefox -- release/videospeed-*.xpi
```

Without Nix, install `web-ext` and run `web-ext lint --source-dir=dist` directly.
The Firefox regression test installs the actual package in a disposable profile and serves
local fixtures at intercepted URLs: Flights must have no controller runtime, while ordinary
pages must retain their controls and speed shortcuts. It does not benchmark the live Google UI.
The inherited `test:e2e` runner targets Chrome; `test:firefox` is the Firefox regression gate.

`make build` produces `release/videospeed-<version>.xpi`. It reuses the existing esbuild
and archive scripts, includes only `dist/`, and does not package development dependencies,
credentials, source maps, or the Git checkout. `npm run release` remains available and runs
the unit/integration tests before building the XPI.

For local testing, disable other video-speed extensions, open `about:debugging`, and load
`dist/manifest.json` as a temporary add-on. Temporary installation does not survive restart.

## Configure the existing owner's account once

Distribution is **public/listed on AMO**, under the same Mozilla account as the tab-group
extension. This fork has a new add-on ID, `videospeed-firefox@njl.dev`; do not use the
codebicycle or nyxar ID. The API credentials determine account ownership, not the GitHub owner
or the email-like add-on ID. A GitHub fork does not inherit repository/environment secrets.

1. Enable workflows on the fork's [Actions page](https://github.com/NickJLange/videospeed-firefox/actions)
   if GitHub prompts for fork approval.
2. In [repository environments](https://github.com/NickJLange/videospeed-firefox/settings/environments),
   use `Mozilla Stuff`. Add NickJLange as a **required reviewer**. Permit
   deployments only from branch `master` and release tags matching `v*`.
3. While signed into the intended Mozilla account, obtain its existing credentials from
   [AMO API keys](https://addons.mozilla.org/developers/addon/api/key/). Add them as environment
   secrets named `AMO_API_KEY` and `AMO_API_SECRET`. Never paste them into issues, chat, or commits.
   Reuse the account's credentials; rotating them could break the tab extension's release job.

An environment name alone is not an approval gate: its required-reviewer rule must be configured
in GitHub. Only the signing job can access the environment secrets. Fork PRs and ordinary branch
pushes run checks but never submit to AMO. Automatic tag submissions fail closed if reviewer
protection is missing or cannot be verified. An explicit manual dispatch with `submit_to_amo`
enabled authorizes submission even before reviewer protection is configured.

## First public submission

1. Review the version and listing content generated by
   `node scripts/amo-metadata.ts > release/amo-metadata.json`. It derives identity from the
   manifest and full license text from `LICENSE`. AMO's predefined GPL choice is GPL-3.0-only,
   so the metadata uses a custom license to preserve **GPL-3.0-or-later**.
2. In **Actions → CI → Run workflow**, select `master` and enable `submit_to_amo`.
3. CI builds and tests the XPI, generates metadata, and archives source from the exact commit.
   Review that commit/version before dispatch; if required reviewers are configured, also
   approve the `Mozilla Stuff` environment deployment.
4. The signing job submits the tested package with `web-ext@10.8.0 --channel=listed`, listing
   metadata, build instructions and corresponding source. The tool can register the first version;
   a separate manual AMO registration is not necessary.
5. The job waits up to 15 minutes for Mozilla approval. On success, download the
   `videospeed-firefox-signed` artifact or install from the new AMO listing. A manually dispatched
   submission does not create a GitHub release.
6. Disable the old controller and test video controls and Google Flights in ordinary Firefox.
   Settings do not automatically migrate between add-on IDs. AMO delivers future listed updates.

Version `0.10.4` is the intended first public version if it has not already been submitted.
Do not submit it twice or tag it for automatic submission after a successful manual submission.

## Later tag releases

Only run these commands when a public release is intended:

```sh
npm version patch --no-git-tag-version
# Update manifest.json to match package.json, then run the checks above.
git add package.json package-lock.json manifest.json
git commit -m "Bump extension version"
git tag "v$(node -p "require('./package.json').version")"
git push origin master
git push origin "v$(node -p "require('./package.json').version")"
```

A `v*` tag runs the same checks and approval-gated submission. Only after signing succeeds
does the release job publish the **signed** XPI and `videospeed-source.zip` on GitHub.
Unsigned build artifacts remain available for debugging but are not published as installable releases.
Submissions are serialized and never automatically retried. Mozilla requires a new version number
for each submission; keep it higher than the previous published version.

## Pending review or failure after submission

A timeout or network failure can happen **after Mozilla has accepted the version**. It does not
cancel or roll back the submission. Do not rerun the signing job blindly: check the
[Developer Hub](https://addons.mozilla.org/developers/) for the add-on and version first.
Review can take longer than the workflow's 15-minute wait.

If the version is pending, wait for approval and obtain its signed XPI from the Developer Hub.
If the workflow stopped before attaching source, upload the matching `videospeed-source.zip`
to that existing version rather than creating a duplicate submission. For a tag release that
timed out, publish the approved XPI and corresponding source manually without rerunning signing.
Only retry submission after confirming no version was created, or follow Mozilla's instructions
for a rejected version.

To archive corresponding source locally, commit all build inputs first, then run:

```sh
git archive --format=zip --output=release/videospeed-source.zip HEAD
```

Never distribute an XPI with source from a different revision. The CI build artifact contains
the tested unsigned XPI, matching source, and generated AMO metadata for recovery.
